> ZIP 내부에서 두 파일이 `pubmed_by_ensemble.py`라는 이름을 공유하지만 실제 내용과 검색 주제가 다릅니다.

## 원본에서 확인된 문제

1. `get_html()`의 재귀 재시도는 횟수 제한이 없어 장애가 길어질 경우 무한 재귀할 수 있음.
2. `final` 버전의 `update_search_term_with_date()`는 단순 `split('AND')`/문자열 결합으로 검색식의 논리 연산자와 괄호를 손상시킬 수 있음.
3. `no_duplication`의 기본 검색식은 여는 괄호가 하나 더 많고, 원래는 연도별 날짜 조건의 후행 괄호에 의존하여 닫히는 구조. 프로필에 그룹 닫는 괄호를 하나 보완함.
4. PubMed HTML의 CSS 클래스에 의존하는 데이터 수집은 페이지 구조 변경 시 실패할 수 있음.
5. 단순 `set()` 변환으로 얻는 PMID 순서는 고정되지 않으며, 페이지/논문별 다중 스레드 호출은 NCBI 요청 제한을 초과할 우려가 있음.
6. 사용된 검색 주제가 서로 다르므로, 특정 1개 버전이 세 코드의 완전한 후속 개정판이라고 보기는 어려움.

## 변경된 설계

- 데이터 소스: PubMed HTML 웹페이지 파싱에서 공식 **NCBI E-utilities(ESearch/EFetch XML)** 로 변경.
- 날짜별 수집: `mindate`, `maxdate`, `datetype=pdat`를 사용한 연도/분기별 범위 검색. 한 범위가 9,500건 초과 시 자동 이분할.
- 중복 제거: 여러 검색식·기간에서 수집한 PMID를 최초 수집 순서대로 유지하며 중복 제거.
- 상세정보: EFetch XML을 배치로 요청하여 기존 10개 CSV 컬럼으로 매핑.
- HTTP 실패: 횟수를 제한한 재시도 및 보수적 요청 간격(기본 API 키 없을 때 0.40초 이상).
- 실행: `search`, `fetch`, `run` 명령으로 분할. PMID 목록을 JSON 체크포인트로 저장하고, CSV는 배치별 flush 및 `--resume` 지원.

## 원본 검색식 재현 범위

- 검색 주제별 PubMed Boolean 검색식을 `config/search_profiles.json`에 보관했습니다.
- 원본 `ensemble` 프로필에는 검색 기간(`2012/01/01`~`2024/08/31`)이 각 검색식 내부에 이미 포함되어 있습니다. `synthetic_biology`도 이 기간이 검색식 안에 포함됩니다. 새 CLI의 날짜는 추가 교집합 필터이므로, 해당 범위 바깥의 자료는 자동 검색되지 않습니다.
- `agri_biotech`는 원래 날짜를 런타임에 붙이던 코드이므로 검색식 본체만 추출하고 괄호만 보정했습니다.
- 검색식을 다른 연도에 적용하려면 `--query`에 날짜 제한을 제거한 독립 검색식을 전달하거나 프로필을 별도로 수정해야 합니다.
- API와 과거 HTML 검색 결과는 인덱스 업데이트·검색 방식에 따라 완전히 일치하지 않을 수 있습니다. 데이터 수집 건수는 실제 실행 뒤 별도 검증해야 합니다.

## 주의

`by_ensemble`은 여러 검색식을 묶어서 실행하는 구현을 가리킵니다. AI 모델의 앙상블 학습/예측 기능은 소스에 없습니다.
